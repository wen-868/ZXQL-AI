## 一、能力总览

智享AI助手具备**被动响应**和**主动服务**两类能力：

```
┌─────────────────────────────────────────────────────────────┐
│                    智享AI 能力体系                           │
│                                                             │
│  ┌─────────────────────┐    ┌─────────────────────────────┐ │
│  │   被动能力（对话驱动） │    │    主动能力（智能驱动）       │ │
│  │                     │    │                             │ │
│  │ 用户说 → AI做        │    │ AI监测 → AI发现 → AI提醒     │ │
│  │ 自然语言 → 意图识别   │    │ 定时巡检 → 异常检测 → 推送   │ │
│  │ → 工具调用 → 结果    │    │ 数据分析 → 建议生成 → 报告   │ │
│  │                     │    │                             │ │
│  │ 覆盖9大业务域        │    │ 覆盖5大场景                 │ │
│  │ 24个业务工具         │    │ 9项主动服务                 │ │
│  └─────────────────────┘    └─────────────────────────────┘ │
│                                                             │
│  触发方式: 用户输入文字/语音    触发方式: 定时任务/事件驱动     │
│  交互模式: SSE流式对话          交互模式: 推送通知/卡片消息    │
│  响应时间: 实时(< 3秒)          响应时间: 准实时(分钟级)       │
```

## 二、被动能力（对话驱动）

> 用户通过自然语言发起请求，AI 理解意图后调用业务工具执行。

### 2.1 销售管理

> **写入规范详见**：[智享AI助手-写入操作规范.md](./智享AI助手-写入操作规范.md)

#### 2.1.1 创建销售单

| 属性 | 内容 |
|------|------|
| **触发方式** | 用户自然语言描述 |
| **核心原则** | 用户说意图 → AI补全规则 → 预览确认 → 执行。**单据完全遵循系统规范，与手动创建一致** |
| **意图识别** | `create_sales_order` |
| **涉及工具** | searchCustomer → searchProduct → checkInventory → createSalesOrder |

**输入示例**：

| 用户输入 | AI解析结果 |
|----------|-----------|
| "给红星商行送10箱五粮液" | 客户=红星商行, 商品=五粮液, 数量=10, 价格=**自动匹配批发价** |
| "红星商行20件五粮液价格980" | 客户=红星商行, 商品=五粮液, 数量=20, 价格=**用户指定980** |
| "给光明超市开个单，雪花啤酒50箱" | 客户=光明超市, 商品=雪花啤酒, 数量=50, 价格=**自动匹配零售价** |
| "顺达批发，金龙鱼调和油30桶，备注月底结账" | 客户=顺达批发, 商品=金龙鱼, 数量=30, 价格=**自动匹配批发价** |

**处理流程**：

```
用户: "给红星商行送10箱五粮液"    ← 没提价格
  │
  ├─ Step 1: 搜索客户 "红星商行"
  │   → 客户ID: c_001, 名称: 红星商行, 类型: 批发客户
  │
  ├─ Step 2: 搜索商品 "五粮液"
  │   → 商品ID: p_052, 五粮液52度500ml
  │   → 零售价: ¥1,200, 批发价: ¥980, VIP价: ¥1,050
  │
  ├─ Step 3: 智能价格匹配
  │   红星商行 = 批发客户 → 自动选用批发价 ¥980/件
  │
  ├─ Step 4: 检查库存
  │   → 当前库存150件，充足 ✅
  │
  ├─ Step 5: 生成预览推送给用户
  │   📋 销售单预览
  │   ┌─────────────────────────────────────────┐
  │   │ 客户     红星商行（批发客户）              │
  │   │ 商品     五粮液52度500ml                  │
  │   │ 数量     10箱（= 60瓶）                   │
  │   │ 换算比   1箱 = 6瓶                        │
  │   │ 单价     ¥163.33/瓶（批发价）              │
  │   │ 合计     60瓶 × ¥163.33 = ¥9,800.00      │
  │   │                                         │
  │   │ ℹ️ 已自动应用批发客户价格                  │
  │   │ ℹ️ 单价以最小单位(瓶)核算                  │
  │   │ 📦 当前库存：150箱（充足 ✅）              │
  │   └─────────────────────────────────────────┘
  │   请确认后执行：[确认] [修改] [取消]
  │
  ├─ Step 6: 用户确认 "确认"
  └─ Step 7: 创建销售单 → 返回单号 SO20260730001
```

**输出示例**：

```
✅ 销售单创建成功

| 项目 | 内容 |
|------|------|
| 单号 | SO20260730001 |
| 客户 | 红星商行（批发客户） |
| 商品 | 五粮液52度500ml |
| 数量 | 10箱 |
| 单价 | ¥980.00（批发价） |
| 合计 | ¥9,800.00 |
| 状态 | 已确认 |
| 备注 | 已自动应用批发客户价格 |
```

**智能价格匹配规则**：

| 客户类型 | 自动选用价格 | 示例 |
|----------|-------------|------|
| 批发客户 | wholesale_price | 红星商行 → 批发价¥980 |
| 零售客户 | retail_price | 光明超市 → 零售价¥1,200 |
| VIP客户 | vip_price | 金钻会员 → VIP价¥1,050 |
| 有合同价 | contract_price（最高优先级） | 大客户 → 合同价¥950 |
| 未分类/新客户 | retail_price（默认） | 新客户 → 零售价 |

> **注意**：以上价格字段名以实际数据库表结构为准。现有系统中 `t_product_price` 表实际字段为 `cost_price`（成本价/采购价）、`retail_price`（零售价）、`wholesale_price`（批发价）、`miniapp_price`（小程序渠道价）、`store_price`（门店售价），暂无 `vip_price`、`min_price`、`contract_price` 字段；`t_product_sku` 表单位字段为 `base_unit`（基础单位）、`box_unit`（组合单位）、`box_ratio`（换算比），暂无 `min_unit` 字段。AI 开发时需对照 `docs/数据库变更清单.md` 和 `docs/init_database.sql` 确认字段名，按客户价格等级（`t_customer_price_binding` + `t_sku_price`）实现 VIP 价/合同价/最低限价等逻辑。

**异常处理**：

| 异常情况 | AI响应 |
|----------|--------|
| 客户不存在 | "未找到'红星商行'，是否要创建新客户？" |
| 商品模糊 | "找到3个匹配商品：①五粮液52度500ml ②五粮液39度500ml ③五粮液1618，请选择" |
| 库存不足 | "五粮液当前库存仅5件，无法满足20件的需求。建议：①减少数量 ②等待补货" |
| 价格未指定 | 自动匹配客户类型对应价格，无需追问 |
| 客户无对应价格 | "五粮液暂无批发价，请手动输入价格" |
| 用户指定价格 < 最低限价 | ⚠️ "价格¥800低于最低限价¥850，确认以此价格出货？"（提示不拦截） |
| 售价低于进货价 | ⚠️ "售价¥130低于采购价¥141.67/瓶，本单预计亏损¥700，确认出货？"（提示不拦截） |
| 超信用额度 | "红星商行信用额度¥50,000，当前已用¥42,000，本次¥19,600将超出额度¥11,600" |

## 三、主动能力（智能驱动）

> AI 在后台持续监测业务数据，发现异常时主动推送提醒和建议。用户无需提问，AI 自动发现并告知。

### 3.1 库存预警

| 属性 | 内容 |
|------|------|
| **触发机制** | 定时巡检（每30分钟）/ 库存变动事件 |
| **检测逻辑** | 当前库存 ≤ 安全库存阈值 |
| **推送渠道** | Web端通知 + 移动端推送 + 对话窗口卡片 |

**触发条件**：

| 条件 | 阈值 |
|------|------|
| 库存低于安全线 | 默认10件（可配置） |
| 近7天日均销量 > 当前库存 | 预计3天内售罄 |
| 爆品库存骤降 | 1小时内销量超过日均3倍 |

**推送示例**：


## 六、自主学习与进化

> **AI不是静态的。系统新增功能后，AI自动感知、学习、纳入能力库，无需人工重新训练或配置。**

### 6.1 核心理念

```
传统方式:
  系统加功能 → 开发写Tool定义 → 部署 → 测试 → AI才能用
  周期: 天级，依赖人工

自主学习方式:
  系统加功能 → AI自动发现 → AI读取文档/代码 → AI理解 → AI立即可用
  周期: 分钟级，零人工
```

### 6.3 学习场景

#### 场景一：新增后端API接口

```
开发者在后端服务新增了 "批量导入销售单" 接口:
  POST /api/admin/sale-bills/batch-import

AI自动学习流程:
  │
  ├─ 1. 发现: 定时扫描后端服务 Swagger 文档，检测到新接口
  ├─ 2. 理解: 读取接口的 path、method、parameters、description
  │     → 接口名: batchImportSalesOrders
  │     → 功能: 批量导入销售单
  │     → 参数: file(Excel文件), customerMapping(客户映射规则)
  ├─ 3. 生成Tool定义:
  │     {
  │       name: "batchImportSalesOrders",
  │       description: "批量导入销售单，支持Excel文件上传",
  │       parameters: { file, customerMapping }
  │     }
```

### 6.4 自动发现机制

```typescript
// brain/auto-learner.service.ts

@Injectable()
export class AutoLearnerService {
  
  /**
   * 定时扫描后端服务 Swagger 文档，发现新接口
   */
  @Cron('*/5 * * * *')  // 每5分钟
  async scanSwaggerDocs() {
    // 单体后端（Express.js）：扫描后端服务的 Swagger 文档
    const swagger = await this.client.get(`http://backend-service:${port}/api-json`);

    // 对比已注册的 Tool，找出新增接口
    const newEndpoints = this.diffEndpoints(swagger.paths, this.knownEndpoints);

    for (const endpoint of newEndpoints) {
      // 自动生成 Tool 定义
      const toolDef = this.generateToolDefinition(endpoint);

      // 注册到 ToolRegistry
      this.toolRegistry.registerDynamic({
        name: toolDef.function.name,
        category: endpoint.tags?.[0] ?? 'default',  // 按路由模块（tags）归类
        definition: toolDef,
        handler: this.createDynamicHandler(endpoint),
      });

      this.logger.log(`自动学习: 新Tool "${toolDef.function.name}" 已注册 (来源: 后端服务 Swagger)`);
    }
  }

  /**
   * 监听数据库 Schema 变更
   */
  async watchSchemaChanges() {
    // 获取当前所有表结构快照
    const currentSchema = await this.getDBSchema();
    
    // 对比上次快照
    const changes = this.diffSchema(this.lastSchema, currentSchema);
    
    for (const change of changes) {
      if (change.type === 'new_table') {
        this.logger.log(`发现新表: ${change.tableName}`);
        // 生成对应的查询Tool
        this.generateTableQueryTool(change.tableName, change.columns);
      }
      if (change.type === 'new_column') {
        this.logger.log(`表 ${change.tableName} 新增字段: ${change.columnName}`);
        // 更新已有Tool的参数定义
        this.updateToolParameters(change.tableName, change.columnName);
      }
    }
    
    this.lastSchema = currentSchema;
  }

  /**
   * 监听知识库文件变更
   */
  async watchKnowledgeBase() {
    const watcher = chokidar.watch('./knowledge/**/*.md');
    
    watcher.on('add', async (filePath) => {
      this.logger.log(`发现新知识文档: ${filePath}`);
      await this.ragEngine.ingestDocument(filePath);
    });
    
    watcher.on('change', async (filePath) => {
      this.logger.log(`知识文档更新: ${filePath}`);
      await this.ragEngine.reingestDocument(filePath);
    });
  }
}
```

### 6.7 安全控制

| 控制项 | 说明 |
|--------|------|
| **手动确认模式** | 默认：发现新功能后通知管理员，确认后才激活（防止误学习） |
| **自动激活模式** | 可选：可信来源（Swagger文档）自动激活，无需确认 |
| **黑名单** | 可配置不自动学习的接口/表（如内部管理接口） |
| **回滚** | 支持一键回滚某次学习结果 |
| **学习日志** | 每次学习记录：来源、时间、生成内容、激活状态 |

### 6.8 与传统方式对比

| 维度 | 传统方式 | 自主学习 |
|------|----------|----------|
| 新功能上线到AI可用 | 1-3天（写Tool定义+测试+部署） | **5分钟**（自动发现+注册） |
| 需要人工介入 | 开发写代码 | **零人工** |
| 覆盖完整性 | 可能遗漏新接口 | **全覆盖**，所有公开API自动学习 |
| 知识更新 | 手动更新文档+重新切片 | **文件变更自动重新向量化** |
| 适用条件 | 任何情况 | 需要Swagger/注释规范的接口 |
