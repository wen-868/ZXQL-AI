> 编制：2026-10-01 · 状态：待审核（审核通过后按批次开工）

## 一、目标与铁律

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **界面零改动** | 只在原型文件末尾追加数据层标记块（`__V15_DATA_START/END__`），移除即逐字节回滚；菜单/布局/组件/样式一概不动 |
| 2 | **数据真实** | 全部来自已上线系统接口（admin-web 同源接口），禁止假数据；接口不可达或字段缺失时回落演示数据，不做编造 |
| 3 | **逐页可验证** | 每页对接完成后立即浏览器验证（表格行/KPI/卡片与线上系统一致），验证不过不进下一页 |
| 4 | **按原型界面层级推进** | 先框架数据层（已就绪）→ 按一级版块（销售→订单→采购→库存→客户→商品→即时零售→财务→报表→营销→系统→工作台）逐版块铺开，每版块内按二级菜单顺序逐页对接 |

## 二、已验证的对接架构（样板：销售单据页 ✓）

```
二级菜单页（SECTORS 103 页）
   ↓ PANEL[t] 渲染器（list/fuse/board/form/…）          ← 界面层，零改动
数据池 DATA[ds]（64 个数据集）+ metricOf(ds) KPI        ← 注入点（只换这里）
   ↑ V15 数据层（纯数据、不可见）：
     ① 自动免密登录 POST /api/admin/auth/demo-login → token（4h）
     ② MAPPERS 逐页登记：真实接口路径 → 行字段映射 → 覆盖 DATA[ds]
     ③ KCALC[ds]：KPI 由真实行计算（包装 metricOf，未对接的回落原演示）
     ④ rerenderIfCurrent：数据到位后重渲染当前页
本地预览：http://127.0.0.1:8788（serve8788.js：静态原型 + /api 反代 api.onepan.cn，解决 CORS）
```

**渲染器分类与数据源**（对接方式由类型决定）：

| 渲染器 | 页数 | 数据源 | 对接动作 |
|---|---|---|---|
| list | ~51 | `SCH[k].ds` → `DATA[ds]` | 覆盖 DATA[ds] |
| fuse | ~25 | `fuse.ds` → `DATA[fuse.ds]`（**注意与 SCH ds 不同名**，如 sale-bills 页 fuse.ds='bill'）+ 卡片 `cards[].ds` | 覆盖 DATA[fuse.ds] + 卡片数据集 |
| board | ~16 | board 分支内取 DATA[xxx]（如 pickup 用 DATA.order） | 按页覆盖对应数据集 |
| form | 8 | 表单默认值 | 默认值接真实数据（低优先级） |
| order/print/pos | 3 | 开单/打印/收银特殊页 | 逐页单独处理 |

**原型数据集行结构基准**（映射目标，共 64 个数据集）：
- 单据类 13 个（saleBill/purchaseBill/returnBill/inBill/pretBill/transferBill/checkBill/deliverBill/reconBill/quoteBill/planBill/contractBill/expenseBill）：`{no,cust,type,items,amt,paid,pay,st,date,op,store}`
- 档案类：customer`{no,name,type,lv,phone,...}`、supplier`{no,name,type,contact,phone,...}`、product`{...GOODS}`、inventory`{...}`、employee`{no,name,dept,post,...}`、store`{no,name,type,addr,...}`
- 流水类：order`{no,plat,cust,amt,st,...}`、pay`{no,dir,cust,acct,...}`、log`{tm,user,mod,...}`、coupon/approval/todo/msg/tag/card/visit/platform/delivery/batch/cost/alert…
- 兜底：generic（占位行——**对接后不允许再出现**）

## 三、流程明细（每页标准作业流程）

每页六步：
1. **核准接口**：以 `admin-web/src/api/*.ts` 实际路径与返回结构为准（原型的 `a` 字段标注仅作参考）
2. **登记 MAPPERS**：`{ds, api, rows(字段映射), kpis(真实计算)}` —— 真实字段 → 原型行结构（如 billNo→no、customerName→cust、receivableAmount→amt、collectionStatus→pay 映射…）
3. **注入验证**：刷新原型 → 点该二级菜单 → 表格行数/首行内容/KPI 与线上系统同页一致
4. **字段缺失处理**：真实接口没有的字段填 `—`（不编造）；原型有而线上无此概念的列保留占位并在回执中登记
5. **卡片核对**：fuse 页附加卡片（cards[].ds）同批接真实数据
6. **回执登记**：每版块完成后登记对接清单（页/接口/映射/验证结果）

## 六、风险与回滚

| 风险 | 处置 |
|---|---|
| 接口与原型标注不一致 | 每页第 1 步"核准接口"以 api.ts 为准；核准结果登记进回执 |
| 真实字段少于原型列 | 缺失字段填 `—` 不编造；整列无数据来源时保留占位并登记（不删列——界面零改动） |
| 大数据量页面（如 524 单） | MAPPERS 按 pageSize 拉 50~200 条（原型表格本身分页展示），不一次性全量拉取 |
| token 过期（4h） | 数据层 401 时自动重新 demo-login 一次 |
| 原型文件被并行修改 | 每批开工前 diff 校验标记块完整；回滚 = 移除标记块逐字节还原 |
| 接口无 CORS（本地预览） | 固定走 8788 反代服务；file:// 直开回落演示数据（明确降级，不报错） |
