# ADR-001：存储形态选型 —— 分形态（standalone 用 LibSQL 嵌入，connected 用 MySQL）

> 状态：**已采纳，A1-spike 验证中（R101-AI-29）** ｜日期：2026-10-13 ｜决策人：凌舟（业主确认）
> 依据：`docs/reports/存储选型评审报告-多维加权-20261013.md`（ZXQL-MS 仓）

---

## 背景

AI 底座当前**强依赖 MySQL + Redis**（云端多租户真源，152 套件/1674 用例全部基于此）。业主新要求：

1. AI 底座**可独立运行**（不依赖管理系统/运营系统），能力对标 DSH/Codex（编程能力后置）
2. 桌面端形态要求**操作越简单越好** ⇒ 不希望用户额外安装/运维数据库服务
3. 但需支持**10 名人类 + 10 名数字员工共享同一份数据**

## 决策

**分形态选型（方案 A）** —— 按 `INTEGRATION_MODE` 装配不同存储：

| 形态 | 存储 | 说明 |
|---|---|---|
| **standalone**（桌面端独立运行） | **LibSQL 嵌入**（单文件 `data/app.db`） | 零服务进程、零安装；随应用目录走；备份=拷文件 |
| **connected**（共享/云端生产） | **MySQL（不变）** | 多租户真源；既有代码/迁移/幂等/审计零改动 |

Redis 同理：standalone 下记忆/限流走**内存 + 持久化**；connected 才启用 ioredis。

## 理由（加权评分结论，权重按业主诉求）

| 候选 | 加权分 | 关键差异 |
|---|---|---|
| **LibSQL 嵌入（standalone）+ MySQL（connected）** | **9.05** | 部署 10（单文件零服务）、向量有升级路径（原生 vector 列 GA）、共享可平滑升级 `sqld`、生产零改动 |
| better-sqlite3 + WAL | 8.45 | 单机最强，但**跨机共享 = SQLite over SMB，官方警告数据损坏风险** |
| 便携 MariaDB | 8.10 | 代码零改动，但每个用户机器/主机要装数据库服务（违背"越简单越好"） |
| PGlite | 7.55 | 太新，TypeORM 无官方 driver |
| DuckDB | 5.75 | 分析型，非 OLTP |

## 关键实测校准（修正了两次误判）

1. **MySQL 耦合面远小于初估**：`ON DUPLICATE KEY` 仅 **4 处**（audit-logger:439/462/494、ai-usage-daily.entity:19）、事务 **1 处**（evolution-version:161）、`FOR UPDATE` 1 处；此前"178 处 NOW()"多数是 JS `Date.now()` 被正则误伤
2. **向量检索与库选型解耦**：`vector-store.service.ts:224-239` 是应用层内存余弦相似度（全量扫描 Top-K），MySQL 仅持久化兜底 ⇒ 但 LibSQL 原生 vector 列提供了**数据量增长后的下推升级路径**（MariaDB 便携版无）

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| TypeORM **1.1.0** 对 LibSQL/SQLite 的 driver 支持未知 | **先做 A1-spike（R101-AI-29）验证可行性**，不盲目改造；不可行则 fallback 到 better-sqlite3(8.45) → 便携 MariaDB(8.10) |
| 迁移双套（mysql/ + sqlite/）长期维护 | 迁移生成器或按形态目录维护；20 表一次性编写后随 schema 演进同步 |
| SQLite 单写队列 | 写批量化（审计已是 fire-and-forget 批处理范式）+ `busy_timeout` 调优 |
| LibSQL 较新 | SQLite 血统（同解析器/文件格式），可回退 better-sqlite3，无锁定 |
| 幂等唯一键语义 | `ON CONFLICT(...) DO UPDATE` ≡ `ON DUPLICATE KEY`；AI-21 反测 5 条将在 sqlite 形态复跑验证 |

## 后续（依赖 spike 结论）

- **A1-spike（R101-AI-29，进行中）**：验证驱动可行性 + 3 实体映射 + 幂等等价 + 迁移双套方案
- spike 通过 ⇒ A2：双 driver 装配 + 018 迁移 sqlite 版 + 反测复跑
- spike 不通过 ⇒ 按 fallback 排序切换，并更新本 ADR

## 不做

- 不改云端生产存储（MySQL 保持）
- 不做分布式多主机数据同步（共享 = 单主机/单库，10+10 规模足够）
- 编程能力（文件/命令/代码工程）后置，不在本决策范围
