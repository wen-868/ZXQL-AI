# AI 底座桌面端 UI 设计方案 v1.0

> 设计人：凌舟｜2026-10-14｜状态：方案稿（业主确认后实施）
> 前置：能力矩阵（业主口径校准版）、办公能力规划清单 v1.0、总设计 v2.0（原生第五业务域）、ADR-001/002
> 现状：`desktop/app/index.html`（47KB/792 行）= **单页对话壳**（chat 滚动区 + 设置抽屉 + 模型/员工列表），**无**办公域/员工管理/多会话 ⇒ 需重新设计

## 一、设计定位（先定边界，避免做成"又一个工作台"）

| 端 | 定位 | UI 导向 |
|---|---|---|
| **AI 底座桌面端**（本方案）| **AI 原生助理 + 数字员工团队 + 轻办公** | **对话驱动**（对话是主入口，一切能力经对话/员工触达）|
| 管理工作台 | 酒水进销存管理 | 业务表单/表格导向 |
| 运营工作台 | 短视频直播运营 | 运营看板/流水线导向 |

**核心差异**：AI 底座端**不是业务系统**，是"AI 助理"—— UI 必须**对话优先、能力后置**，业务系统端才是"表单优先"。

│   · 待办  │  └──────────────────────────┘ │  · 员工任务状态   │
│   · 审批  │  ┌─ 数字员工─────────────────┐ │                  │

│   · 会议  │  └──────────────────────────┘ │                  │

### ① 导航栏（左侧，可折叠）
| 项 | 说明 | 对应能力 |
|---|---|---|
| **对话** | 主入口；多会话管理（新建/切换/删除）| chat（已有）+ 多会话（**新增**）|
| **数字员工** | 员工列表/派单/任务状态/结果回传 | employee 体系（已有能力，**无管理面**）|
| **办公**（二级）| 文档/待办/审批/日程/会议/通知 | **新增原生域**（规划清单 O1~O5）|
| **知识库** | 文档库/检索/入库 | RAG（已有能力，**无管理面**）|
| **设置** | 服务地址/账号/模型/权限/关于 | 已有（抽屉）⇒ 升级为页 |

### ② 主工作区
- **对话**：消息流（text 增量）+ **工具时间线**（tool_start/tool_result）+ **写确认卡**（preview + expireAt 倒计时 + needsSecondConfirm）+ clarify 澄清 + done(usage)
- **数字员工**：员工卡（岗位/职责/状态）+ 派单（对话式）+ 任务看板 + 结果回传（AI 生成式）
- **办公域**：每域一个视图（列表 + 详情 + AI 辅助操作）

### ③ 上下文面板（右侧，可折叠）
当前会话上下文、我的待办、待我审批、最近通知、员工任务状态 —— **把"主动能力"从"推送打扰"变为"可见可查"**

### ④ 输入区（底部）
附件 / 语音（ASR/TTS 已有）/ 模型选择（多 provider）/ 工具状态 / 发送 —— 现有雏形升级

## 三、核心交互流程（对话驱动的关键 4 条）

### 流程 1：对话 → 写确认（已有，须保留）
```
用户说"创建销售单…" → AI 调 createSalesOrder(confirm=false)
→ 预览卡（含警告/expireAt）→ 用户确认 → 执行 → 结果 + 撤销提示
```

### 流程 2：对话 → 派单数字员工（**新增 UI 面**）
```
用户说"让小李核对本月库存" → AI 调 dispatchEmployeeTask
→ 员工任务卡（含任务/时限/回传目标）→ 员工执行 → 结果回传本会话
```

### 流程 3：办公域对话式操作（**新增**）
```
用户说"把这份合同归档，提醒我周三付款" → AI 建待办 + 归档文档
→ 上下文面板"我的待办"即时可见 + 到期经 proactive 推送
```

### 流程 4：主动能力触达（**从推送到可查**）
```
巡检发现库存预警 → WebSocket 推送 → 通知铃红点 → 右侧面板可查 → 点击跳转对话上下文
```

## 四、与现有 UI 的关系（改造策略）

| 层 | 处理 |
|---|---|
| Electron 壳（main.js/preload.js）| **不变**（无边框/去 Origin/窗口桥，封装标准 v1.0 已验证）|
| 视觉语言 | 沿用融合版品牌（同色系/同图标体系），保证三端统一 |
| 对话区/确认卡/模型选择 | **保留并升级**（这是已验证可用的部分）|
| 单页 → 多 Tab 架构 | **重构**（新增导航/员工/办公域/多会话）|
| 对接层 | **扩展**（补办公域 API / 员工管理 API / 多会话 API）|

## 五、设计原则（红线）

1. **对话优先**：任何能力都能经对话触达；UI 面板是"对话的可视化补充"，不是唯一入口
2. **能力渐进**：按办公规划五批点亮（文档→待办→审批→日程会议→通知），**每批一个域**，UI 同步开一个 Tab
3. **零重复登录**：三端同一总台账号（已定）；AI 底座端不造登录体系
4. **桌面端特性**：多窗口/托盘/离线提示（standalone 模式可见性）—— 属 Electron 壳扩展
5. **不做**：复杂表单设计器/企业 OA 工作流（定位轻办公）/深色主题外的多主题（一期）

## 七、待业主确认（5 项）

1. **定位**：AI 底座端 = "AI 原生助理+数字员工+轻办公"（对话驱动），**不做成业务工作台** —— 认可？
2. **IA**：左侧导航（对话/数字员工/办公六域/知识库/设置）+ 中部 Tab + 右侧上下文面板 —— 认可？
3. **第一批 UI 范围**：随 O1 文档中心，先做「对话重构（多会话+时间线）+ 文档域 Tab」？还是先做完整导航框架（Tab 为占位）？
4. **视觉**：沿用融合版品牌语言？还是要为 AI 端单独定一套（更"AI 感"）？
5. **数字员工管理面**：UI 上要做到多细（派单/看板/回传/绩效）？
