# 代码审查规范（验收检查项：代码审查）

> 更新：2026-08-15 ｜ 目标：每 PR 至少 1 名非作者审批，审查记录可追溯

## 一、审查流程

1. 开发者在功能分支提交，推送到 GitHub 后发起 PR（使用 `.github/pull_request_template.md` 模板）
2. CI 自动执行：单测 + lint + coverage 门禁 + 三端构建 + flow/QA 回归 + CodeQL SAST
3. 审查者（CODEOWNERS 指定）审阅：
   - 功能与需求一致性、边界与异常处理
   - 数据安全（SQL 注入/越权/敏感信息）与幂等性
   - 测试覆盖：新逻辑必须有对应单测/集成测试
   - 数据库迁移幂等性与文档同步
4. 至少 1 名非作者 approve 后合并（建议启用 GitHub Branch Protection 强制）
5. 合并后 CI 自动部署（deploy.yml），审查记录留存在 PR 中可追溯

## 二、保护分支配置建议（仓库管理员执行）

在 GitHub 仓库 Settings → Branches → Add rule 配置 main 分支：
- Require a pull request before merging（至少 1 个 approval）
- Require status checks to pass（CI：build-and-test）
- Do not allow bypassing the above settings

## 三、审查清单要点

- 支付/库存/权限类改动：必须复核事务一致性、幂等与越权校验
- 登录/认证类改动：必须复核防爆破、会话安全、密钥管理
- 新增接口：入参 zod 校验、统一返回体、鉴权与租户隔离
- 前端改动：类型检查通过、无硬编码敏感信息、错误提示可理解
