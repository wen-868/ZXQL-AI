# 生产安全核查记录

> 本文件记录对生产环境的**只读探测**发现。探测仅用于可用性验证与风险排查，
> 未做任何写操作、未导出任何凭据。

## 一、[P0] 生产开放免密登录，且直接授予超级管理员（2026-09-27 发现）

| 项 | 实测 |
|---|---|
| 端点 | `POST https://api.onepan.cn/api/admin/auth/demo-login` |
| 请求体 | `{}`（**无任何凭据**） |
| 响应 | `HTTP 200 {"code":"0","msg":"成功","data":{"token":"<JWT>"}}` |
| JWT payload | `{"id":3,"username":"demo","realName":"演示账号","roles":["SUPER_ADMIN","STORE_OPERATOR"],"storeId":null,...}` |

**风险**：任何知道该地址的人，无需账号密码即可拿到 **`SUPER_ADMIN`** 令牌，
进而以最高权限调用管理系统与 AI 底座的全部接口（含写操作审核确认、员工管理、配置下发）。
`storeId: null` 意味着**不受门店数据范围约束**。

**建议处置**（需你在平台侧操作，本仓改不动）：

1. **首选**：生产环境禁用 `demo-login` 端点（按 `NODE_ENV` 或开关配置短路，返回 404/403）；
2. 若必须保留演示能力：仅允许内网/白名单 IP，且**不得授予 `SUPER_ADMIN`**，改为只读演示角色；
3. 轮换现有演示账号密钥，并检查该账号近期是否产生异常审计记录。

**顺带说明**：本仓基准/种子脚本原通过该端点取 token（`perf-bench` / `tool-bench` / `seed-employees`），
等于把 P0 漏洞固化成一条自动化利用路径。**已于 2026-10-03 改造完毕**（见下节），生产禁用该端点不再影响本仓脚本。

## 一之二、本仓侧已修：脚本鉴权改造 + 生产门控（2026-10-03）

新增 `scripts/lib/bench-auth.js`，三个脚本统一走 `resolveAdminToken({ authBase })`，取 token 优先级：

| 优先级 | 方式 | 触发条件 |
|---|---|---|
| 1 | 显式 token | 调用方 argv 传入，或环境变量 `AI_BASE_TOKEN` |
| 2 | **真实登录** | `AI_BASE_USERNAME` + `AI_BASE_PASSWORD` 同时提供 → `POST {authBase}/api/admin/auth/login`，body `{username,password}` |
| 3 | 演示登录 | 以上都没有时；**仅限本地/内网地址**，生产域名直接拒绝 |

**生产门控**：`authBase` 主机名不属于 `localhost / 127.x / 10.x / 192.168.x / 172.16-31.x / ::1` 时，
若未提供真实凭据则**在发出任何请求之前**抛错退出，并提示改用真实登录；应急可用 `ALLOW_DEMO_LOGIN=1` 放行。

实测（`node scripts/perf-bench.js https://saas.onepan.cn/ai-api https://api.onepan.cn 1`）：

```
基准测试失败: 拒绝在非本地地址 api.onepan.cn 使用免密 demo-login。
  该端点免密即返回 SUPER_ADMIN JWT（P0）。请改为真实登录：
    AI_BASE_USERNAME=<账号> AI_BASE_PASSWORD=<密码> node scripts/<脚本>.js ...
  应急可用 ALLOW_DEMO_LOGIN=1 强制放行（会留痕于生产日志，不建议）。
EXIT=1
```

> 即：平台侧禁用 `demo-login` 后，本仓脚本**照常可用**（传真实凭据即可），
> 且在禁用之前也不会再用免密超管去打生产。

## 二、附带发现：部署与数据库结构不同步（2026-09-27）

代码已由流水线自动部署、进程健康检查正常，但**迁移只应用到 006**，007/008/009 未执行，
导致所有对话报错、数字员工功能不可用。详见 `migrations/README.md` 第五节「生产补齐」。

> 教训：**健康检查通过 ≠ 服务可用**。`api/health` 只反映进程存活，不校验依赖的表结构；
> 长期未跑的真实链路（如一次对话）才暴露问题。建议把"迁移是否已应用"纳入部署后自检。
