# 密钥与敏感配置管理规范（验收检查项：存储安全/KMS）

> 更新：2026-08-15 ｜ 目标：敏感信息零硬编码、密钥集中管理、逐步迁移 KMS

## 一、当前密钥与敏感配置清单（2026-08-15 审计）

| 类别 | 配置项 | 存放位置 | 现状 | 迁移计划 |
|---|---|---|---|---|
| 后端密钥 | JWT_SECRET / CSRF_SECRET | `backend/.env`（不入库，.gitignore） | ✅ 生产启动时校验非占位符并动态生成 | KMS 托管 |
| 数据库 | DB_PASSWORD | `backend/.env` | ✅ 不入库 | KMS 托管 |
| 支付 | 微信支付 APIv3 密钥、商户号、证书序列号 | `t_payment_config`（is_encrypted=1 加密存储） | ✅ 加密存储 | 保持 + KMS 主密钥 |
| 支付 | 支付宝私钥 | `t_payment_config`（加密） | ✅ 加密存储 | 保持 |
| 短信 | 阿里云/腾讯云 AccessKey | `t_sys_config`（加密）/ `.env` | 🟡 部分在 .env | KMS 托管 |
| 小程序 | AppSecret | `t_sys_config`（加密） | ✅ 加密存储 | 保持 |
| 平台 | SERVICE_ACCOUNT_CLIENT_ID/SECRET | `.env` | ✅ 不入库 | KMS 托管 |
| CSRF 会话 | 前端加密 storage（AES） | 客户端本地 | ✅ 加密存储 | 保持 |

## 二、红线要求

1. 密钥严禁硬编码进代码/提交进仓库（CI 会拦截：.env 已 gitignore）
2. 数据库敏感列一律 is_encrypted=1（t_sys_config / t_payment_config 已支持）
3. 生产 .env 由 auto-deploy.sh 启动时校验占位符并动态生成，防止弱密钥
4. 前端不存储任何服务端密钥，仅存会话令牌（加密 storage）

## 三、KMS 迁移计划（P0，待云账号开通）

1. 阿里云/腾讯云开通 KMS，创建主密钥（Customer Master Key）
2. backend `config/env.ts` 增加 KMS 解密分支：.env 存 KMS 密文（Envelope Encryption），启动时解密注入
3. 数据库敏感列的加密密钥从硬编码密钥切换为 KMS 生成的数据密钥（DEK）
4. 密钥轮换：主密钥每年轮换 + 数据密钥自动重加密脚本
5. 验证：渗透测试前完成，密钥可审计、可吊销

## 四、审计命令

```bash
# 检查仓库是否误入密钥（CI 前人工执行）
grep -rn "sk_live\|AKIA\|-----BEGIN.*PRIVATE" --include="*.ts" --include="*.vue" --include="*.js" backend/src admin-web/src saas-admin/src app-mobile/src | grep -v __tests__ || echo "无密钥泄露"

# 检查 .env 是否含占位符（生产部署脚本已自动处理）
grep -c "CHANGE_ME\|REPLACE_ME" backend/.env || echo "无占位符"
```
