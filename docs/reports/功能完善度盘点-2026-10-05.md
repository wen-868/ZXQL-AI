## 四、几处统计口径的自我更正（避免误判）

盘点过程中我先后做了两次错误判断，已核实纠正，记录在此以免后续复现：

1. **"tools模块 57/65 无 spec" —— 误报**。实际 54个是声明式 `*.tool.ts`（`{name, description, args, execute}` 字面量，无需单测），核心逻辑文件（`tool-executor` / `tool-registry` / `customer-scope.guard` / `circuit-breaker`）**都有 spec**，只是文件名带 `.service` / `.guard` 后缀，不匹配朴素的 `xxx.ts → xxx.spec.ts` 规则。
2. **"database 模块 22 文件 0 spec" —— 非缺口**。全为 TypeORM entity 与 module，属声明式，无可测逻辑。
3. **`ENABLE_RAG` / `WEEKLY_PLAN_CRON_ENABLED` 默认值矛盾 —— 误报**。代码默认均为 `'false'`，与 `.env.example` 一致；首次 grep 未捕获 `get<string>(key, 'false')` 的第二参数形式。
