     该池不放弃重连，所以 Redis 恢复后缓冲立即可用；若改用 `stop-after-3` 池，Redis 抖动 3 次后该池停摆、
     重放队列会静默失效到进程重启 ⇒ 故选 retry-forever，理由已写进类注释。
  2. **重试预算在进程内**：`attempts`/`dueAt` 是内存 Map ⇒ 进程重启后某条条目的重试次数从 0 重新计。
     这不构成无限重试（每轮上限仍生效），但**跨重启的累计次数不做持久化**（需要持久化就得给条目加 DB 行/改表，
