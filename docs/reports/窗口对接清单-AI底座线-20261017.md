## 8. 验收纪律（每条"通过"都要过这两关）

1. **能回答"如果这功能坏了，我这条会不会红？"** —— 只有 mutation 是可靠检验
2. **门禁全绿 ≠ 功能真的通**：本轮实证 = 182 套件全绿但整族工具没接进执行器；
   同理"部署日志成功"≠"新工具可用" ⇒ **判上线用行为探针**（直调工具看响应），且探针自身要拿已知项做对照（老工具能执行 ⇒ 探针可信）
3. 无效 mutation 三态：改语法致 `Tests: 0 total` / prettier 重排致替换未命中 / 夹具挂错租户致恒绿空转
4. **校验器本身要被校验**；形状断言要断到关键内容（"有三支 OR"不够，要断"授予支带 granted 集"）
5. 迁移：双套（MySQL `NNN` + `migrations-sqlite/NNN`）+ **必须真跑 MySQL scratch**（1071 只有真库暴露）；scratch 前置依赖与迁移序列对齐
6. 环境：junction worktree 禁 pnpm[168]；共享 worktree 禁 git 写[165]；临时库要 `STANDALONE_DB_PATH` 隔离；基线用 `migrations-sqlite/000_baseline.sql` 而非 `synchronize:true`
7. `idem_key` 存加盐哈希（用 `handle.idemKey`）；SSE 字段是 `tool` 非 `toolName`
