## 三、状态机（本批核心）

```
        submit=false                submit=true
            │                           │
            ▼                           ▼
        ┌────────┐   提交(审核后)   ┌──────────┐   approve   ┌──────────┐
        │ draft  │ ───────────────▶ │ pending  │ ──────────▶ │ approved │ 终态
        └────────┘                  └──────────┘             └──────────┘
             ▲                          │  │ reject   ┌──────────┐
             │ 仅 draft 可改            │  └────────▶ │ rejected │ 终态
     aiApprovalUpdate                   │             └──────────┘
                                        │ cancel(申请人/平台)  ┌───────────┐
                                        └───────────────────▶ │ cancelled │
                                                              └───────────┘
```
- **原子迁移**：`UPDATE ... WHERE status='pending'`；`affected=0` ⇒ 再读 ⇒ **明确失败并如实告知当前状态**
- 🔴 **互斥终态不可回放**：与 `aiTodoComplete`（完成无歧义 ⇒ 回放）**刻意不同** —— 并发者可能做了**相反**决定（approved vs rejected），回放成成功=撒谎 ⇒ **明确失败 + 告知当前结果**（凌舟已入规范）
- `aiApprovalCancel` **复用同一基类**（仅覆写权限口径：申请人），状态机/原子迁移**一份不复制**

## 八、自我报备（事故与教训）

| # | 事件 | 处置 |
|---|---|---|
| 1 | **harness 漏默认参数**（`createHarness(opts: {...})` 无 `= {}`）⇒ 3 处调用 tsc 报错、运行时 `opts=undefined` **被工具 try/catch 吞成 `success:false`** ⇒ 3 例"假失败" | 补 `= {}`；教训：**harness 工厂必须给默认参数**，否则错误被"禁抛契约"掩盖成业务失败 |
| 2 | **无效 mutation（第 3 次踩）**：替换文本 `const visibility = true // MUT ? [base]` 改了语法 ⇒ `Tests: 0 total` | 改用**单行/正则**变异；教训：变异**不得改动语法**，且必须确认"测试真跑了" |
| 3 | **替换未命中**：单行目标被 prettier 重排 ⇒ `目标存在:false`（看似"没红"，实为未变异） | 改**正则（格式无关）**变异 |
| 4 | 🔴 **自审发现的漏测**：④ 只断言"有三支 OR + tenant"，**未断言 ACL 授予支内容** ⇒ 清空授予集也不会红 | **补断言**（`opValue(branches[0].id) === ['7']`）后 mutation 才真红；已入规范自检问句 |
| 5 | 迁移 `related_biz` 可空 ⇒ 唯一键**不判重** | 工具注释写明"**业务层承重**"+ 业务幂等前置检查 + DB 竞态兜底 |
