### 3.1 复探（2026-10-03 14:00 UTC，两轮法，结论不变）

改用**两轮探测**（第一轮无 token 只能看到 401，**探不到业务层**；第二轮取 token 穿透鉴权），
避免把 401 误读成"端点正常"：

| 端点 | 第一轮（无 token） | 第二轮（带 token） |
|---|---|---|
| `GET /api/health` | ✅ 200 | — |
| `POST /api/chat` | 401 | ❌ 201 + SSE error：`Unknown column 'PlatformAiConfigEntity.evolution_auto_activate'` |
| `GET /api/ai/employees` | 401 | ❌ 500 `Table 'liquor_inventory.t_ai_employee' doesn't exist` |
| `GET /api/admin/ai-db/versions` | — | ❌ 500 `Unknown column 'v.regression_accuracy'` ← **本轮新发现** |
| `GET /api/admin/ai-db/experiences` | — | ✅ 200 |
| `GET /api/admin/ai-db/samples` | — | ✅ 200 |
| `GET /api/admin/ai-db/e4/readiness` | — | ✅ 200 |
| `GET /api/admin/audit-logs` | — | ⚠️ 200 但 `total:0`（空表，见下） |
| `POST /api/admin/auth/demo-login` | ❌ **200，仍免密放行** `roles=["SUPER_ADMIN","STORE_OPERATOR"] storeId=null` | — |

**新发现（`v.regression_accuracy`）**：该列属 `migrations/007_e5_auto_close.sql` 第 29-31 行声明，
已核对文件确认无误。说明 **007 未应用不仅影响对话，还连带打挂了进化版本列表端点**——
即"迁移停滞"的爆炸半径比首轮探测看到的更大（对话 + 数字员工 + 进化版本，共三处功能不可用）。

**新疑点（审计表通但 0 条）**：`GET /api/admin/audit-logs` 返回 200 且 `total:0`。
这与"009 未应用"看似矛盾（若表结构缺失应 500）。两种可能：
① 表结构在、但生产从未发生过审计写入（对话全失败 → 无从写审计，逻辑自洽）；
② 查询层对缺失列做了降级/兜底，掩盖了 009 未应用。
**仅靠 HTTP 响应无法区分**，需在生产库直接执行 `SHOW COLUMNS FROM t_ai_audit_log LIKE 'categories'` 判定。

> 探测方法教训：**401 只说明鉴权生效，不说明业务可用**。评估线上必须带有效 token 打真实链路，
> 否则会把"被拒绝"误判成"正常"。本轮两次探测脚本均为临时脚本，用完即删，未入库。
