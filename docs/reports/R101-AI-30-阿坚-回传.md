## 打包形态结论（单包兼容 x64 + arm64）— 凌舟补充指令单列

### 现状（本机实测的配置事实）
| 项 | 值 |
|---|---|
| 桌面工程 | `desktop/`（Electron `^33.0.0` + electron-builder `^26.15.3`，本机已装 electron-builder **26.15.3**） |
| 现产包目标 | `win.target = [{nsis, arch:['x64']}, {portable, arch:['x64']}]` ⇒ **当前只出 x64**（且是"每架构一个包"的形态） |
| better-sqlite3 | **尚未进任何 package.json**（第 2 步引入，需 `^12`） |
| 本机架构 | `PROCESSOR_ARCHITECTURE=ARM64`（Windows on ARM），Node `win32/arm64` |

### 可行性判定（明确口径）
- **electron-builder 原生不支持** Windows"单安装器含双架构"：`arch` 数组只会产出**每架构各一个**安装包；
  跨架构合并仅 macOS 有 `universal` 目标。Windows 下 NSIS 模板按构建架构铺一套 app 载荷。
- ⇒ **"一个包发所有用户"需要自研一层 NSIS 逻辑**（electron-builder 允许 `nsis.include` 注入自定义宏），
  这不是"不可行"，而是"**不在 electron-builder 开箱能力内**"。

### 推荐实现方案（可行路径，按代价排序）
| 方案 | 做法 | 代价 |
|---|---|---|
| **甲（推荐）：单安装器 + 双载荷** | 安装包内放两份运行时载荷：`payload/x64`（Electron x64 + better-sqlite3 x64 native）与 `payload/arm64`（Electron arm64 + arm64 native）；`nsis.include` 注入 `customInstall` 宏，用 `${If} ${IsNativeARM64}` / 探测 `PROCESSOR_ARCHITECTURE` 决定复制哪一份到安装目录 | 安装包≈2×（粗估 350~450MB）；需自研/维护 NSIS 脚本；**x64 native 需在 x64 工具链下产出**（本机 arm64 可用 better-sqlite3 prebuild 直接取 x64 产物，Electron 本体取官方 x64 包即可） |
| 乙：单"引导安装器" | 一个薄安装器按架构**下载/释放**对应架构的正式包（或静默调用内置子安装器） | 需分发源/网络；离线场景不成立 |
| 丙：双包（各自 x64/arm64） | electron-builder 默认能力，零自研 | **不满足业主要求**（"一个包"），仅作 fallback |
| 丁：只做 x64 靠仿真 | x64 Electron 在 arm64 Windows 可跑（含 x64 native） | **红卡明确禁止**静默降级；且性能/兼容风险自担 |

### 尚需实测的项（第 4 步，未完成，不虚报）
1. 产出 x64 侧 `better-sqlite3` native：需确认本机是否具备 x64 目标工具链（VS Build Tools x64）或走 `prebuild-install --arch=x64` 取预编译产物；
2. arm64 侧 native（本机可编/可装）；
3. 自研 NSIS 宏：安装时探测架构 → 复制对应载荷 → 校验 `better-sqlite3` 可 `require`（非仿真）；
4. 双机实测：x64 机器安装启动 + standalone 完整对话；arm64 机器（本机）同样。
   **这些都需要真实构建运行**，本步只交付"配置事实 + 可行性判定 + 方案"；若第 1 项工具链缺失，我会立即按红卡报卡点，不静默改口径。
