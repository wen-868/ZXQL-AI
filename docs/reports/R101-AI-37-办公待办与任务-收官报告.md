## 四、暗坑与教训（怎么发现、怎么修）

| # | 暗坑/事故 | 发现方式 | 修复/教训 |
|---|---|---|---|
| 1 | 🔴 **空转守卫**：租户比较写成"自己比自己"（恒真）⇒ 隔离失效 | 自审新代码时发现（**lint/tsc 均不报**） | 改为与 `ctx.tenantId` 比较；补专例 ⑪ + mutation（自比 ⇒ ①⑪ 同红）<br>**教训：泛化时先确认"拿谁来比"** |
| 2 | **构造参数顺序隐性契约** | 5 例红 → 加 `DBG_ACL` 日志见 `WHERE={"tenantId"}` | spec 显式按新序 + 注释；**改签名必须同步调用方** |
| 3 | **`where` 匹配 NULL 不能传 `null`** | `tsc` 拒绝 `dueAt: dueAt ?? null` | 用 `IsNull()`（语义更正确） |
| 4 | **反向假红**：桩把 `LessThanOrEqual.type` 当 `'lte'` | 首跑 5 例红（功能其实正确） | 桩同时认 `lte`/`lessThanOrEqual`<br>**教训：桩与真实库语义不一致会同时制造假绿与假红** |
| 5 | **无效 mutation**：替换文本带注释 ⇒ 注释掉实参 ⇒ `Tests: 0 total` | 自审 mutation 输出（不是 1 failed 而是 0 total） | 改无注释精确替换<br>**教训：mutation 前后都要确认"测试真跑了"** |
| 6 | **sqlite 增量放 ACL 索引会在改名之前执行** | 编写期推理（新库顺序） | ACL 通用化整体移到 applier（改名类语句本就无法纯 SQL 幂等） |
| 7 | **旧唯一键过窄** | 编写期推理：`(doc_id,principal…)` 会让 `todo#5` 与 `doc#5` 冲突 | applier/migration 显式 DROP 旧键 + 建 `(resource_type,resource_id,principal…)` |
| 8 | **applier 假阴性核验**（查旧索引名 ⇒ 一直打印 false） | 跑 applier 时对照输出 | 同步为通用唯一键名 |

## 六、可复用结论（供批次 3 审批流）

1. **权限泛化范式**：资源 = `{resourceType, resourceId, tenantId, owner}`；判定一处；域差异只在薄适配（`archived` 这类规则属域，不属 ACL）
2. **防重按语义选**：重复建单⇒幂等键（双层防 NULL 语义差）｜改状态⇒**接口拒绝**（把状态变更挤到专用工具）｜重复操作⇒**原子条件 + affected 判定**
3. **列表类工具双层防线**：**库层条件**（限制泄漏面）+ 逐行确认（权威判定）；大集合绝不用"加载后过滤"
4. **跨域联动先划边界**：能复用就复用（**结构上不给第二条路径**：不注入 `ServiceClient`）；不能复用就**报卡点独立立项**，不打临时补丁
5. **mutation 三纪律**：替换必须命中断言目标、替换不得改动语法、必须确认测试真跑了（`0 total` 即无效）
6. **泛化自检清单**：① 拿谁来比（空转守卫）② 构造参数顺序 ③ NULL 匹配用算子 ④ 唯一键维度是否够宽 ⑤ 桩与真实库语义一致
