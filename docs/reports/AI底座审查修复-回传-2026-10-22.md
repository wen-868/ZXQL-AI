```typescript
function meta(mod: unknown, key: string): unknown[] {
  return (Reflect.getMetadata(key, mod) ?? []) as unknown[];
```

after（:31-34）：

```typescript
// 注：`mod` 必须是 `object`（而非 `unknown`）——Reflect.getMetadata 的 target
```

### 2.5 F-2 行为不变性证明（默认配置 `http://127.0.0.1:11434`）

**口径来源（Read 核实，非转述）**：

1. `src/evolution/e4-distillation.service.ts:111-113`：`OLLAMA_BASE_URL` 默认值 = `http://127.0.0.1:11434` ✓（与派单一致）
2. `src/providers/ollama.provider.ts:100`：`strictEgress: false`（注释「env 默认端点（本地 ollama）= 平台/环境维护 ⇒ 不挂商家端点守卫」）✓
3. `src/common/outbound-target.guard.ts:239-253`：`axiosEgressOptions(strict)` —— `if (strict !== true) return {};`，只有 `true` 才返回 `{lookup, beforeRedirect, proxy:false}`

**推论链**：

```
OLLAMA_STRICT_EGRESS = false
  ⇒ axiosEgressOptions(false)
  ⇒ 返回 {}（outbound-target.guard.ts:244-246）
  ⇒ axios 请求配置不含 lookup / beforeRedirect / proxy:false
  ⇒ ①不挂公网 HTTPS 守卫，127.0.0.1 与内网地址均放行
    ②不禁用环境代理 ⇒ 代理行为与改动前 fetch 一致
  ⇒ 默认配置下蒸馏行为与改动前完全一致
```

**未触碰红线**：未调用 `assertAllowedOutboundUrl`，未引入 strict 守卫。
（对照：`assertAllowedOutboundUrl` 会拒 `127.0.0.1`——见 `external-model.outbound-bypass.spec.ts:181`
`expect(() => assertAllowedOutboundUrl('https://@127.0.0.1/')).toThrow(…)`，故本单禁用。）

**超时语义等价**：`AbortSignal.timeout(E4_TRAIN_TIMEOUT_MS)`（fetch 的总耗时上限）⇒ `timeout: E4_TRAIN_TIMEOUT_MS`
（axios 的请求总耗时上限）。两者超时后均抛错进入既有 `catch`，文案 `Ollama 不可达或超时（…）` 不变 ✓

**错误文案结构不变**：`{ok:false, message}` 两种分支（HTTP 非 2xx / 网络不可达超时）均保留，
`validateStatus: () => true` 是专门为了让非 2xx 仍走「HTTP xxx」分支而非被 axios 抛进 catch ✓
调用方 `src/gateway/ai-db.controller.ts:221` 仅消费 `{ok, modelName, samples, message}`，契约未改 ✓

## 6. 风险与自我报备

1. **残余风险（F-2 语义细节）**：`fetch` 的 `AbortSignal.timeout` 与 axios `timeout` 均为「请求总耗时上限」，语义等价；但 axios 的 `timeout` 不含响应体流式读取完成前的时间差异（此处 `responseType: 'text'` 会读完再 resolve，故等价）。若将来改为流式消费需重新评估。
2. **残余风险（F-2 未做端到端验证）**：因 jest 不可用，未能实跑蒸馏成功/失败两条路径的真实断言；行为不变性目前由代码口径（§2.5）+ 类型/lint 门禁背书，非运行时实测。建议优先级 3 落地后补跑 `e4-distillation.service.spec.ts`。
3. **CI 时长**：新增全量 tsc 步骤会让 CI 增加一次类型检查耗时（本地实测约 1-2 分钟量级，未精确计时），未调整 `timeout-minutes: 20`。
4. **派单卡路径小误差（已按代码为准）**：卡上写的 `src/ai/providers/ollama.provider.ts` 实际为 `src/providers/ollama.provider.ts`；`strictEgress: false` 位于 :100，与卡述一致，未影响口径判断。
